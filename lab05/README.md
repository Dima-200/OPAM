## Завдання 1. Дужки ( ) [ ] { } (a = 0)

Функція `CheckBrackets` повертає результат і індекс першої помилки або −1.

| Рядок | Результат | Індекс помилки |
|---|---|---|
| `(a[b]{c})` | збалансований | −1 |
| `([)]` | незбалансований | 2 |
| `)(` | незбалансований | 0 |
| `((` | незбалансований | 0 |
| `` (порожній) | збалансований | −1 |

Рядок з K = 6 відкривальними і K − 1 = 5 закривальними дужками: `(((((()))))` — незбалансований, програма повернула індекс **0** (найраніша незакрита дужка).

Дві обов'язкові перевірки: закривальна дужка при порожньому стеку (тест `)(`) і непорожній стек після кінця рядка (тест `((`).

## Завдання 2. Зворотний польський запис (b = 3: + − * / min max)

| Вираз | Результат |
|---|---|
| `3 4 + 2 *` | 14 |
| `5 3 -` | 2 |
| `8 2 /` | 4 |
| `2 3 4 * +` | 14 |
| `5 0 /` | помилка: ділення на нуль |

Власний вираз на K = 6: `8 2 / 5 max 1 +` → 8/2 = 4, max(4, 5) = 5, 5 + 1 = **6** (три операції: `/`, `max`, `+`).

Некоректний вхід: `3 abc +` → невідомий токен; `1 2` → забагато чисел; `1 +` → не вистачає чисел. У всіх випадках повідомлення, без винятку.

## Завдання 4. Власний стек IntStack

Початкова місткість K % 4 + 2 = 4. Кількість Push: K % 4 + 3 = 5, подвоєння відбувається на 5-му Push.

```
Push(10): Count = 1, Capacity = 4
Push(20): Count = 2, Capacity = 4
Push(30): Count = 3, Capacity = 4
Push(40): Count = 4, Capacity = 4
Push(50): Count = 5, Capacity = 8
```

Завдання 1 переписане на `IntStack` (стек кодів символів + окремий стек індексів), результати збігаються зі стандартним `Stack<T>` на всіх тестах.

## Завдання 5. Чому саме ця структура

**Завдання 1 (дужки): стек.** Закривальна дужка має закривати найостаннішу ще не закриту відкривальну — задача вимагає порядку «останній прийшов — перший вийшов», бо дужки вкладені одна в одну. Якби взяли чергу, закривальна дужка порівнювалась би з найпершою відкритою: на правильному рядку `(a[b]{c})` перша ж дужка `]` зустрілась би з `(` і програма хибно оголосила б рядок помилковим.

**Завдання 2 (зворотний польський запис): стек.** Операція застосовується до двох найновіших результатів, тобто до тих, що лежать зверху. Якби взяли чергу, операція брала б найстаріші числа: у `2 3 4 * +` множення отримало б 2 і 3 замість 3 і 4, і результат був би 10 замість 14.

**Завдання 3 (обслуговування): черга.** Заявки мають оброблятися в порядку надходження: кожен обслуговувач, що звільнився, бере найстарішу з тих, що чекають. Якби взяли стек, першою обслуговувалась би найновіша заявка, а заявка №1 могла б чекати найдовше; змінились би всі часи початку й завершення.

**Чому `Queue.Dequeue()` дешевший за `List.RemoveAt(0)`.** `Queue<T>` усередині тримає масив зі «зсувним» початком (кільцевий буфер): `Dequeue` просто пересуває голову на одну позицію, тому коштує однаково за будь-якої довжини черги. `List.RemoveAt(0)` мусить зсунути на одну позицію **кожен** наступний елемент, тому час росте разом з кількістю елементів.

Мої заміри з Лабораторної 4: `[ВСТАВ СВОЇ ЧИСЛА З ЛАБИ 4: час Dequeue і час RemoveAt(0) для тих самих розмірів]`.

## Крайові випадки

| Вхід | Завдання | Очікувано | Отримано |
|---|---|---|---|
| порожній рядок | 1 | збалансований, −1 | збалансований, −1 |
| порожній рядок | 2 | повідомлення про помилку | помилка: порожній вираз |
| рядок без жодної дужки (`abc`) | 1 | збалансований, −1 | збалансований, −1 |
| вираз з одного числа (`7`) | 2 | 7 | 7 |
| ділення на нуль (`5 0 /`) | 2 | повідомлення про помилку | помилка: ділення на нуль |
| жодної заявки | 3 | повідомлення, без падіння | «Заявок немає, моделювати нічого.» |
| Pop на порожньому стеку | 4 | виняток, який перехоплено | `InvalidOperationException` перехоплено, програма не падає |

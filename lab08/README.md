# Алгоритми пошуку та їх порівняння

N=3, K=6, a=0, b=3, c=3

**Розмір масиву:** 100000  
**X=60, Y=72, відсутнє значення=121**

## Мета роботи

Реалізувати та дослідити лінійний, бінарний, експоненційний пошук і пошук межі. Порівняти алгоритми за кількістю порівнянь та часом виконання, дослідити типові помилки бінарного пошуку.

## Параметри варіанта

- Тип даних: `int[]`.
- Кількість елементів: 100000.
- Діапазон випадкових значень: [0; 120].
- Генератор випадкових чисел: `new Random(3)`.
- Основне значення пошуку: `X = 60`.
- Верхня межа діапазону: `Y = 72`.
- Відсутнє значення: `121`.
- Основний запит: кількість елементів у діапазоні [60; 72].

## Завдання 1. Лінійний пошук

Реалізовано узагальнений лінійний пошук, який приймає масив, шукане значення та компаратор `Func<T,T,int>`.

Результати:

| Значення | Індекс | Кількість порівнянь |
|---|---:|---:|
| 60 | 49434 | 49435 |
| 0 | 0 | 1 |
| 121 | -1 | 100000 |

**Висновок:** лінійний пошук перевіряє елементи послідовно. Найкращий випадок — шуканий елемент знаходиться на початку масиву. Найгірший — елемент відсутній або знаходиться наприкінці масиву.

## Завдання 2. Бінарний пошук

Реалізовано узагальнений бінарний пошук для відсортованого масиву. Для обчислення середини використовується безпечний вираз:

`mid = lo + (hi - lo) / 2`

Результати:

| Значення | Індекс | Кількість порівнянь |
|---|---:|---:|
| 60 | 49999 | 1 |
| 0 | 780 | 7 |
| 121 | -1 | 17 |

### Дослідження поломок

**Поломка 1. Умова `while (lo < hi)` замість `while (lo <= hi)`.**

На масиві `[0, 1]` під час пошуку `1` алгоритм повернув `-1` замість індексу `1`.

Причина: цикл завершується, коли `lo == hi`, тому останній елемент не перевіряється.

**Поломка 2. Присвоєння `lo = mid` замість `lo = mid + 1`.**

На масиві `[0, 1]` під час пошуку `1` за 10 ітерацій алгоритм не завершив пошук.

Причина: нижня межа не змінюється, коли `mid == lo`. Це може спричинити нескінченний цикл. Для демонстрації помилки було використано обмеження кількості ітерацій.

**Поломка 3. Обчислення середини `mid = (lo + hi) / 2`.**

Таке обчислення може спричинити переповнення типу `int`, якщо сума індексів перевищує `int.MaxValue`.

Для масиву довжиною від 1 073 741 825 елементів переповнення вже потенційно можливе.

На масиві з 100000 елементів помилка не проявилася: індекс знайдено правильно, за 1 порівняння.

Правильний варіант:

`mid = lo + (hi - lo) / 2`

**Поломка 4. Використання бінарного пошуку на невідсортованому масиві.**

Було виконано 100 запитів до наявних у масиві значень. У 87 випадках алгоритм повернув `-1`.

Причина: бінарний пошук працює правильно лише тоді, коли масив відсортований відповідно до використаного компаратора.

## Завдання 3. Пошук межі

Реалізовано узагальнений пошук межі `BoundarySearch`, який приймає монотонну умову та повертає індекс першого елемента, для якого ця умова істинна. Якщо такого елемента немає, повертається `a.Length`.

Результати:

| Операція | Індекс / результат | Порівняння |
|---|---:|---:|
| LowerBound(60) | 49434 | 16 |
| UpperBound(60) | 50276 | 16 |
| Кількість елементів, рівних 60 | 842 | — |
| Кількість елементів у [60; 72] | 10790 | 33 |

Для підрахунку діапазону використано дві межі:
- перший елемент, який не менший за 60;
- перший елемент, який більший за 72.

Різниця між цими індексами дорівнює кількості елементів у заданому діапазоні.

Перевірка лінійним підрахунком дала такий самий результат — 10790 елементів, але потребувала 150566 перевірок.

### Перевірка неузгодженої умови

Для перевірки було використано умову «значення кратне 7».

`BoundarySearch` повернув індекс 80924, тоді як справжній перший індекс елемента, кратного 7, — 0.

Результат неправильний.

Причина: умова кратності 7 не є монотонною на відсортованому масиві. Вона може багаторазово змінюватися з істинної на хибну та навпаки. Тому бінарний пошук межі для неї використовувати не можна.

## Завдання 4. Експоненційний пошук

Реалізовано експоненційний пошук із подальшим бінарним пошуком у знайденому інтервалі.

Алгоритм перевіряє позиції 1, 2, 4, 8, 16 і так далі, доки не буде знайдено межу інтервалу. Після цього виконується бінарний пошук.

Результати:

| Значення | Бінарний пошук: індекс | Бінарний: порівняння | Експоненційний: індекс | Експоненційний: порівняння |
|---|---:|---:|---:|---:|
| 60 | 49999 | 1 | 50176 | 23 |
| 0 | 780 | 7 | 0 | 1 |
| 121 | -1 | 17 | -1 | 34 |

Для значення 60 алгоритми повернули різні індекси, оскільки в масиві є повторювані значення. Обидва індекси містять шукане значення.

**Висновок:** експоненційний пошук ефективний, коли шуканий елемент розташований близько до початку масиву. Для елементів наприкінці або відсутніх значень він може виконувати більше порівнянь, ніж звичайний бінарний пошук.

Теоретична складність:
- Лінійний пошук: O(n).

У цьому експерименті дані містять лише 121 можливе значення (від 0 до 120), тому багато елементів повторюються. Бінарний пошук може знайти будь-яке входження шуканого значення, тому середня кількість порівнянь у нього виявилася невеликою.

За отриманими вимірюваннями лінійний пошук виявився швидшим для всіх перевірених кількостей запитів. Сортування масиву потребує додаткового часу, тому для невеликої кількості запитів воно не окупається.

Часові результати можуть залежати від середовища виконання, прогріву JIT-компілятора, навантаження комп'ютера та інших чинників.

## Завдання 6. Контрольні питання

**1. За якого значення q сортування окупається порівняно з лінійним пошуком? Чому результат може відрізнятися від теоретичної оцінки?**

У проведених вимірюваннях сортування з бінарним пошуком не стало швидшим навіть за 100 запитів. Теоретична оцінка точки окупності залежить від вартості сортування, кількості запитів та вартості одного пошуку. Реальний результат також залежить від обладнання, реалізації алгоритмів та середовища виконання.

**2. Які два запити може ефективно виконати бінарний пошук, але для яких HashSet або Dictionary не є прямою заміною?**

- Знайти індекс першого елемента, який не менший за задане значення.
- Порахувати кількість елементів у заданому відсортованому діапазоні за допомогою двох меж.

HashSet і Dictionary ефективні для перевірки наявності елемента, але не призначені для пошуку меж у відсортованому порядку.

**3. Що краще використовувати, якщо дані постійно змінюються після кожного запиту?**

Якщо потрібна лише перевірка наявності елемента, доцільно використовувати HashSet або Dictionary. Вони забезпечують швидкий пошук і зручне додавання та видалення елементів.

Якщо потрібні запити за діапазоном або пошук меж, хеш-таблиці не є прямою заміною бінарного пошуку. Для таких задач варто використовувати структури даних, які підтримують упорядкованість.

## Висновок

Під час лабораторної роботи було реалізовано лінійний, бінарний, експоненційний пошук і пошук межі з використанням узагальнених методів та компаратора.

Було досліджено чотири типові помилки бінарного пошуку: неправильну умову циклу, відсутність зміщення нижньої межі, переповнення під час обчислення середини та використання невідсортованого масиву.

Експеримент показав, що бінарний пошук значно зменшує кількість порівнянь на відсортованих даних. Експоненційний пошук особливо корисний для елементів на початку масиву. Пошук межі дає змогу ефективно визначати кількість елементів у заданому діапазоні.

Також було перевірено крайові випадки та порівняно алгоритми за кількістю порівнянь і часом виконання.

**Отже, вибір алгоритму пошуку залежить від структури даних, їх упорядкованості та кількості запитів.**
